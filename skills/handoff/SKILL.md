# Handoff 交接文档

把长会话的关键上下文沉淀到 `HANDOFF.md`，让完全没有上下文的新会话可以无缝接手。核心是写一份「给陌生同事看的交接笔记」，不是给当前会话存档。

## 写交接文档（会话结束前）

当用户说「这个会话要结束了」「写交接文档」等时：

1. 回顾整个会话，写以下五部分：
   - **我们在做什么任务**：当前目标、背景，一句话说清。
   - **已经完成了什么**：已完成的工作、产出文件的路径、验证结果。具体到文件路径和命令。
   - **当前卡在哪**：阻塞点、未解决的问题、已尝试但失败的做法。
   - **下一步计划**：明确的下一步动作，按优先级排。
   - **踩过的坑（绝对不要再踩）**：每条用「不要做 X，要做 Y」的格式写，附原因。

2. 写入 `HANDOFF.md`（覆盖旧内容，不留历史版本）：
   - 默认写到**当前工作目录**。若会话运行在项目子目录（如 `ninebot-rn`），写在子目录，方便新会话原地读取。
   - 用中文写，与用户语言一致。
   - 所有路径、命令、文件引用必须具体准确，禁止模糊表述。

3. 写完后，用一句话确认文件位置，例如：「交接文档已存到 `HANDOFF.md`」。

## 读交接文档（新会话开始）

当用户说「先读 HANDOFF.md」或类似的话时：

1. 先看当前工作目录有没有 `HANDOFF.md`；没有则逐级向父目录查找。
2. 读取后，向用户复述交接要点（任务、进度、卡点、下一步），并确认从哪一步继续。

## 要点

- HANDOFF.md 是给「完全没有上下文的新会话」看的，必须自包含、可独立执行。
- 踩坑部分只写真正重要、值得记住的坑，别凑数。
- 新会话读完并确认接手后，即可按「下一步计划」继续工作。
